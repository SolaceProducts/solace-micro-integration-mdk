# Generate Consumer

This file generates the consumer-specific binder implementation: the inbound channel adapter, acknowledgment callback, consumer destination record, and the consumer integration test. All shared infrastructure (properties, IOUtil, provisioner, binder class, configuration, META-INF) is already generated by `generate-shared.md`, and shared test infrastructure (profile YAML files, TestApplication, AbstractBase) is already generated by `generate-common-tests.md`, before this file is invoked. The consumer-specific test class is generated by `generate-consumer-tests.md` (delegated from Step 4).

**Step execution order is mandatory.** Each step must complete successfully before the next step begins. Do not skip ahead, parallelize steps, or begin a step while a previous step is incomplete. If a step fails, stop and report the failure — do not proceed to subsequent steps.

## Transformation Rules

These rules apply to **every** file generated from an ABC template in this file. Verify each rule before writing any file.

1. **Package**: Replace `com.solace.samples.binder.abc` with `{BINDER_PACKAGE}` in all package declarations and imports.
2. **Class names**: Replace `Abc` prefix with `{TECH_NAME_CLASS_NAME_USE}` in class names, constructors, and cross-references.
3. **Connection config prefix**: Replace `"abc"` with `{BINDER_CONNECTION_PREFIX}` in `@ConfigurationProperties` annotations for connection properties.
4. **Extended binding prefix**: Replace `"spring.cloud.stream.abc"` with `{EXTENDED_BINDING_PREFIX}` in extended binding properties and `DEFAULTS_PREFIX` constants.
5. **Binder name**: Replace `abc` with `{BINDER_NAME}` in `spring.binders`, per-binding `binder`, multi-binder `type`, and log messages.
6. **SDK alignment**: SDK client class, connection pattern, poll/read methods, ack/reject methods, and exception handling must match CLAUDE.md SDK Client section. If CLAUDE.md is incomplete or ambiguous, consult `configuration.md` first, then the technology overview report at `{TECH_OVERVIEW_PATH}` (referenced in `configuration.md`). For binder SPI integration patterns (how to wire the SDK into the inbound adapter), refer to the ABC template project as the working example. Do not carry over ABC-specific API calls — adapt the pattern to the target SDK.
7. **No leftover template references**: Generated files must not contain `com.solace.samples`, `abc`, `Abc`, or `ABC` (except in comments that explicitly reference the template origin).
8. **All imports explicit**: No wildcard imports.
9. **No useless comments**: Do not carry over template boilerplate comments. Only retain comments that provide genuine value.

## Step 2: Generate acknowledgment callback

**Blocked by:** Step 1 must complete successfully.

Read the ABC template `AbcAcknowledgmentCallback.java` for the structural pattern.

| Blueprint | Output |
|---|---|
| `{ABC_MAIN}/inbound/acknowledge/AbcAcknowledgmentCallback.java` | `{BINDER_TARGET_SRC_DIR}/inbound/acknowledge/{Tech}AcknowledgmentCallback.java` |

**Transformation rules (in addition to general rules):**

- Replace package, class names, and imports
- Replace `AbcClient` with the actual SDK client class from CLAUDE.md SDK Client section
- **`acknowledge(Status status)`** — the ABC template logic is the pattern to follow:
  1. Guard against double-ack with `AtomicBoolean`
  2. `ACCEPT` → call SDK's ack/confirm method from CLAUDE.md **SDK Client** section. If the SDK has no explicit ack method (e.g., messages are auto-removed on read), this becomes a no-op with a comment explaining why.
  3. `REJECT` / `REQUEUE` → call SDK's reject/nack method from CLAUDE.md **SDK Client** section. If the SDK has no reject method, this becomes a no-op with a comment.
- Replace `abcClient.acknowledgeMessage(destination, messageId)` with the target SDK's equivalent
- Replace `abcClient.rejectMessage(destination, messageId)` with the target SDK's equivalent

## Step 3: Generate inbound channel adapter

**Blocked by:** Step 2 must complete successfully.

Read the ABC template `AbcInboundChannelAdapter.java` for the structural pattern.

| Blueprint | Output |
|---|---|
| `{ABC_MAIN}/inbound/AbcInboundChannelAdapter.java` | `{BINDER_TARGET_SRC_DIR}/inbound/{Tech}InboundChannelAdapter.java` |

**Transformation rules (in addition to general rules):**

- Replace package, class names, and imports
- Replace `AbcClient` with the actual SDK client class from CLAUDE.md SDK Client section
- Replace `IOUtil.createAbcClient(...)` with `IOUtil.create{Tech}Client(...)`
- Replace `AbcInboundMessage` with the SDK's inbound/read message type from CLAUDE.md **SDK Client** data types section
- Replace `AbcAcknowledgmentCallback` with `{Tech}AcknowledgmentCallback`
- Replace `AbcConsumerDestination` with `{Tech}ConsumerDestination`
- Replace `AbcConsumerProperties` with `{Tech}ConsumerProperties`
- **`doStart()`** — create client via IOUtil. Call client start/connect if the SDK requires an explicit connect step. Start the polling scheduler.
- **Polling loop** — the ABC template logic is the pattern to follow:
  1. Poll using the SDK's read/poll method from CLAUDE.md **SDK Client** retrieve methods
  2. If message present: extract payload and headers, create Spring `Message<?>` with `MessageBuilder`
  3. Attach `{Tech}AcknowledgmentCallback` as a header for downstream ack handling
  4. Send to output channel via `sendMessage()`
  5. On success: auto-ack if `noAutoAck` is not set
  6. On processing error: requeue (retry) — call SDK's requeue method or equivalent
  7. On conversion error: delegate to a private `handleConversionError(callback, exception)` method. Wrap the logic in a try/catch: **try** — call inherited `sendErrorMessageIfNecessary(null, e)`; if it returns `true` (error channel handled it) → auto-ack; if `false` (no error channel) → reject (DLQ). **catch** — log both errors, then reject (DLQ) as fallback.
- **`doStop()`** — shut down the polling scheduler gracefully, close/disconnect client using the SDK's close method from CLAUDE.md
- **Polling interval**: Read from `{Tech}ConsumerProperties.getPollingInterval()` — configurable per binding via extended binding properties
- **Concurrency**: The ABC template uses a configurable worker pool size — adapt if the target SDK supports concurrent consumers
