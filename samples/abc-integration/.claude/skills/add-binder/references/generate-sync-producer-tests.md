### Test pattern

Each sync producer test follows the same three-phase flow. The **universal** parts (StreamBridge, error channel, `MessagingException` assertion) are the same for every technology. The **SDK-specific** parts differ per technology — use CLAUDE.md, then `configuration.md`, then the overview report at `{TECH_OVERVIEW_PATH}` for the SDK details.

1. **Setup (SDK-specific)** — destinations are already created by `AbstractBaseWithOnTheFlyContainerIT.@BeforeAll` using the SDK client.
2. **Publish (universal)** — build a Spring `Message<?>` with `MessageBuilder`, send via `streamBridge.send(outputBindingName, testMessage)`. The binder receives the message and publishes it synchronously to the technology backend.
3. **Verify (SDK-specific)** — use the SDK client directly to retrieve/poll the data that the binder published, and assert on payload and headers.

**Key difference from async producer tests:** No `PublishAcknowledgmentCallback` is used. The sync path throws `MessagingException` on failure instead of invoking a callback. No ack callback assertions appear in any test method.

### Scope

This test class has exactly **5 test methods** — matching the ABC template. The first 4 test the producer messaging behaviour, the 5th verifies binder health. Do not add additional test methods.

### Transformation rules (in addition to general rules)

- Package declaration → `{BINDER_PACKAGE}`
- Import `TestApplication` with `{BINDER_PACKAGE}.app.TestApplication`
- **Active profile override**: The generated class must override `getActiveProfiles()` to return `new String[]{"sync-producer"}`. This activates `application-sync-producer.yml`, which contains only the producer function definition, producer binding, and producer extended properties.

**SDK type replacements** — read from CLAUDE.md **SDK Client** data types section, fall back to overview report at `{TECH_OVERVIEW_PATH}`:

### Test methods

1. **`testProducerBindingSuccessfulPublish`** — happy path: message published synchronously and verified via SDK
   - Annotated with `@Order(1)`
   - **Payload type**: use the preferred supported payload type from CLAUDE.md **Key Design Decisions** (e.g., `String`, `byte[]`). The ABC template uses `String` — adapt if the target SDK requires a different type.
   - **Publish** (universal): `streamBridge.send(outputBindingName, testMessage)` — stays as-is
   - **Verify** (SDK-specific): replace `containerWrapper.getClient().pollMessage(TARGET_DESTINATION)` with the target SDK's read/poll method. Read the method signature from CLAUDE.md **SDK Client** retrieve methods, or from the overview report. The return type, optional/list wrapping, and awaiting pattern must match the SDK.
   - **Payload assertion** (SDK-specific): replace `resp.getPayload()` with the SDK's message body accessor. Read from CLAUDE.md **SDK Client** data types section.
   - **Header assertion** (SDK-specific): replace `resp.getHeaders()` with the SDK's header/metadata accessor. Read from CLAUDE.md **SDK Client** data types section.
   - **Filtered header assertion** (universal): `doesNotContainKeys("id", "timestamp", "target-protocol")` — the binder must always filter these Spring internal headers
   - **No ack callback assertion** — sync path does not use `PublishAcknowledgmentCallback`

2. **`testProducerBindingSuccessfulBatchPublish`** — batch happy path: batch of messages published synchronously and each verified individually via SDK
   - Annotated with `@Order(2)`
   - **Build batch** (universal): generate 2 test payloads using `Stream.generate(() -> ...).limit(2).toList()`. Generate a matching `List<MessageHeaders>` with per-message headers (e.g., `Map.of("test-header", "abcd")`). Build a `Message<?>` with `MessageBuilder.withPayload(testPayloads)` and set header: `BinderHeaders.BATCH_HEADERS` → the batched headers list.
   - **Publish** (universal): `streamBridge.send(outputBindingName, testMessageBatch)` — stays as-is
   - **Verify** (SDK-specific): iterate `testPayloads`, for each expected payload poll from `TARGET_DESTINATION` using the SDK's read/poll method. Assert payload matches and per-message headers are present. Assert filtered headers (`id`, `timestamp`, `target-protocol`) are absent.
   - **No ack callback assertion** — sync path does not use `PublishAcknowledgmentCallback`

3. **`testProducerBindingFailedPublish`** — failure path: invalid destination triggers `MessagingException`
   - Annotated with `@Order(3)`
   - **Publish** (universal): uses `BinderHeaders.TARGET_DESTINATION` with an invalid destination to trigger failure
   - **Exception assertion** (universal): `assertThatThrownBy(() -> streamBridge.send(outputBindingName, testMessage)).isInstanceOf(MessagingException.class)` — the sync path throws `MessagingException` directly, unlike the async path which invokes `onPublishFailure`
   - **Error channel assertion** (universal): `application.readMessageReceivedOnErrorChannel(...)` verifies the original payload

4. **`testDynamicDestinations`** — dynamic routing: message arrives at overridden destination
   - Annotated with `@Order(4)`
   - **Publish** (universal): uses `BinderHeaders.TARGET_DESTINATION` with `DYNAMIC_DESTINATION`
   - **Verify at dynamic destination** (SDK-specific): poll from `DYNAMIC_DESTINATION` using the SDK read/poll method — same adaptation as test 1
   - **Verify not at bound destination** (SDK-specific): poll from `TARGET_DESTINATION` and assert empty/not-present — same SDK method, expect no result
   - **No ack callback assertion** — sync path does not use `PublishAcknowledgmentCallback`

5. **`testHealth`** — verifies binder health endpoint reports UP status
   - Annotated with `@Order(5)` — **must run last**. Producer binder health is lazy: the health indicator only initialises after the first publish attempt. Running this test before the publish tests would fail because no client connection exists yet. The `@Order(5)` annotation and a comment explaining this ordering constraint are mandatory.
   - Uses `getMockMvc().perform(get("/actuator/health"))` from the base class
   - Asserts:
     - `status().isOk()`
     - `jsonPath("components.binders.components.{BINDER_NAME}").exists()`
     - `jsonPath("components.binders.components.{BINDER_NAME}.status").value("UP")`
   - Everything else (MockMvc injection, GET path, status check, value `"UP"`) — universal, copy as-is from the ABC template
