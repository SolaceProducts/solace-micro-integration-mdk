# Configuration Variables

All variables used by skills to bootstrap and generate a new micro-integration project.

---

## 0. Target Folder

| Variable | Example Value | Configuration Value | Description |
|---|---|---|---|
| `TARGET_PROJECT_FOLDER` | `c:/your/path/new-project-name` | | Filesystem path where the new project will be created |

---

## 1. Technology Identity

| Variable | Example Value | Configuration Value | Description |
|---|---|---|---|
| `TECH_NAME_LOWER` | `abc` | | Lowercase technology name. Used in: binder name, package segments, config property prefixes, folder names |
| `TECH_NAME_UPPER` | `ABC` | | Uppercase technology name. Used in: constant names, comments, log prefixes |
| `TECH_NAME_CLASS_NAME_USE` | `Abc` | | Technology name as it should appear in Java class name prefixes (e.g., `AwsSqs`, `MongoDB`, `ActiveMQ`). Cannot be derived mechanically — set to the official/conventional capitalisation |

## 1b. Technology Research

> **Note:** The file at `TECH_OVERVIEW_PATH` must only be read when a skill explicitly requires it in its own instructions. Do not read this file during configuration parsing or validation — it is a large document and loading it unnecessarily adds context that most skills do not need.

| Variable | Example Value | Configuration Value | Description |
|---|---|---|---|
| `TECH_OVERVIEW_PATH` | `overview-abc.md` | | Path (relative to workspace root) to the technology overview report generated by `analyze-integration-tech`. Used as a verified source of SDK classes, Docker images, Testcontainers modules, and configuration properties. **Read only when a skill step explicitly instructs it — do not preload.** |

## 4. Binder Development Configuration

Variables used by the `init-mi-project` and `add-binder` skills. `BINDER_BUILD_PARENT_VERSION` is used by `init-mi-project` to set the binder module's parent POM version. The remaining variables are used by `add-binder` for source generation.

| Variable | Example Value | Configuration Value | Description |
|---|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---|---|
| `BINDER_BUILD_PARENT_VERSION` | `3.1.2`                                                                                                                                                                        | | `pubsubplus-connector-component-build-parent` version. Parent POM for the binder module — controls framework dependency versions and build plugin configuration |
| `BINDER_TYPE` | `producer` | | Comma-separated list of binder capabilities to generate: **producer** = outbound, **consumer** = inbound. Use `producer,consumer` to generate both. Unsupported directions throw `UnsupportedOperationException` |
| `BINDER_PACKAGE` | `com.solace.samples.binder.abc` | | Java package for all binder source files. Used in package declarations, imports, `@ConfigurationProperties`, and META-INF registrations |
| `BINDER_SKIP_GENERATION` | `false` | | Set to `true` to skip custom binder generation entirely. Automatically implied when `BINDER_3PARTY_SOURCE_URL` is set. When `true`, the `add-binder` skill exits immediately, `init-mi-project` skips creating the binder module directory structure, and the micro-integration POM uses `BINDER_3PARTY_DEPENDENCY` instead of the custom binder module |
| `BINDER_3PARTY_SOURCE_URL` | `https://github.com/spring-cloud/spring-cloud-stream/tree/main/binders/pulsar-binder` | | GitHub URL of an existing third-party Spring Cloud Stream binder for the target technology. When set, a custom binder is **not** needed — the `add-binder` skill should skip generation and reference this binder instead. Leave empty when no third-party binder exists and a custom binder must be generated |
| `BINDER_3PARTY_DEPENDENCY` | `<dependency><groupId>org.springframework.cloud</groupId><artifactId>spring-cloud-stream-binder-kafka</artifactId><version>5.0.1</version><scope>compile</scope></dependency>` | | Complete Maven `<dependency>` element for the third-party binder. Only set when `BINDER_3PARTY_SOURCE_URL` is provided. This dependency replaces the custom binder module in the micro-integration application POM |

## 5. Micro-Integration Development Configuration

Variables used to generate the micro-integration Spring Boot application module — the runtime connector that bridges the Solace event broker and the target technology via Spring Cloud Stream.

| Variable | Example Value | Configuration Value | Description |
|---|---|---|---|
| `MI_PACKAGE` | `com.solace.samples.microintegration` | | Java package for all micro-integration application source files. Used in package declarations, `@SpringBootApplication` base package, and component scan |
| `MI_CONTAINER_IMAGE_NAME` | `solace-micro-integration-abc` | | OCI container image name for the packaged micro-integration. Used in build plugin configuration (Jib / Spring Boot Maven Plugin) |

## 6. Platform & Framework Versions

| Variable | Example Value | Configuration Value | Description                                                                                                                                                                                                          |
|---|--------------------------------|---|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `MICRO_INTEGRATION_PLATFORM_BOM_VERSION` | `3.1.2`                        | | `micro-integration-platform-bom` version. Manages Spring Boot, Spring Cloud, Testcontainers, Solace micro-integration versions                                                                                       |
| `MICRO_INTEGRATION_BUILD_PARENT_VERSION` | `3.1.2`                        | | `micro-integration-build-parent` version. Parent POM for the micro-integration module                                                                                                                               |
| `JDK_PATH` | `C:/Program Files/Java/jdk-17` | | Path to the JDK installation directory. Set as `JAVA_HOME` when executing the Maven wrapper                                                                                                                          |
| `JAVA_VERSION` | `17` | | Java compiler source/target/release version, numeric value                                                                                                                                                          |
| `HOST_OS` | `windows` | | Host operating system (`windows` or `linux`) where code generation agent will be executed. macOS uses `linux`. Determines path separators, shell commands (`cmd` vs `bash`), and script extensions (`.cmd` vs `.sh`) |
